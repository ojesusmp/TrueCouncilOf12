Philosophy

Two buildings, two philosophies:

The American Building

Impressive and tall. Built for the moment. Sometimes a wind or earthquake is devastating.

The Japanese Building

Withstands earthquakes because every force is accounted for in advance. Worst-case-first. Built to last.

The Council of 12 follows the Japanese approach: 12 lenses that together account for every force acting on any situation. Solomon ensures nothing is missed and the solution works for now while being upgradeable to the ideal.

Core Principle These are lenses, not personalities. Each seat examines a fundamental dimension that any problem touches. The same 12 questions work on a code PR, a legal filing, a career crossroads, or a family decision. No domain presets needed.

The 12 Seats

Organized into 4 phases that define the execution order. Each phase establishes a foundation the next phase builds on.

GROUND — Establish Reality

Before we can judge, constrain, or imagine, we must know what is actually true.

Seat 1
Truth / Evidence
"What do we actually know?"
Seat 2
Context / Pattern
"What led here?"
Seat 3
Systems / Root Cause
"What is the real mechanism?"

BOUND — Establish Constraints

Reality is established. Now draw the boundaries.

Seat 4
Ethics / Conscience
"Is this right?"
Seat 5
Rules / Constraints
"What are the hard boundaries?"
Seat 6
Human / Emotional
"How will people actually feel?"

STRESS — Pressure Test

If it survives STRESS, it deserves to exist.

Seat 7
Adversarial / Attack
"How would someone break this?"
Seat 8
Risk / Fragility
"What goes wrong by accident?"
Seat 9
Resource / Tradeoff
"What does this really cost?"

ELEVATE — Expand Options

Look up. What can actually be done, who else matters, and what are we not seeing?

Seat 10
Execution / Feasibility
"Can we actually do this?"
Seat 11
Voiceless / Absent
"Who has no voice?"
Seat 12
Innovation / Possibility
"What better option exists?"

Solomon — The Coordinator

Solomon is not a thirteenth lens — he is the integrator who sits above the 12 seats. He is both the gatekeeper (triage) and the judge (synthesis): he opens the process by choosing the mode and closes it by delivering the verdict — always one of PROCEED, REVISE — needs: [X], or STOP. Never "it depends."

Solomon's Meta-Lenses

Three perspectives Solomon applies during synthesis that require seeing the full picture:

Behavioral

Why are people really acting this way? Hidden motivations, ego, fear, tribalism, self-preservation.

Strategic

Who benefits? Who loses? Where is the leverage? What move changes the board?

Meta-Lens

Meaning

Who are we becoming through this decision? What story does this create in 5 years?

Solomon's Process

  1. Hear all seats
  2. Reject lies, panic, ego, and false urgency
  3. Apply meta-lenses (Behavioral, Strategic, Meaning)
  4. Balance short-term and long-term
  5. Protect truth, people, and consequences
  6. Make the call — name the tradeoff, own the sacrifice
The Rule Solomon always names the tradeoff. "We sacrifice X to protect Y because Z." Never "we need to balance multiple factors." A verdict without a named sacrifice is not a verdict.

Hardened Mechanics (v3 → v4)

MechanismWhat it guarantees

Execution Modes

Solomon reads the situation first, assesses complexity, and recommends a mode. You confirm or override.

A
Essential Five
< 60 seconds
5 seats: Truth, Systems, Human, Adversarial, Voiceless

For quick decisions, low-stakes choices, time-pressured situations. Self-contained in SKILL.md alone.
B
Full Council
< 3 minutes
All 12 seats + Solomon synthesis

For important decisions, deliverable reviews, moderate stakes. Loads phase files for full seat definitions.
C
Full Pipeline
3 – 9 minutes
All 12 seats + extended analysis + reconciliation

For high-stakes decisions: legal, financial, production, public-facing. Maximum depth.

Model Compatibility (capability bands)

BandSupported ModesDefault
FRONTIER (top-tier reasoning)A, B, CB
MID (strong general models)A, BB
COMPACT (small/fast models)A onlyA

Model names map to bands in exactly one place: the Model → Band Table in SKILL.md. Unknown model? The skill assumes MID, says so, and proceeds. If Solomon recommends a mode your model's band doesn't support, it auto-downgrades with an explanation.

Escalation Suggestions

Once a session is already running, Solomon may recommend a deeper mode (and waits for your confirmation) when he detects:

  • High-stakes deliverables (legal, financial, public-facing)
  • Deliverables being handed off to someone else
  • Work you'll be held accountable for

Outside a session, Claude may at most mention in one sentence that the Council is available — never convene it unasked.

Examples

Quick Decision (Mode A)

/c12 My manager just asked me to work Saturday. I have family plans.
Should I accept, negotiate, or decline?
What you get Solomon recommends Mode A. Five seats give 1-2 sentence insights each. Solomon delivers a verdict with a named tradeoff in under 60 seconds.

Deliverable Review (Mode B)

/TrueCouncilOf12 Review this deployment guide before I send it to the client.
[paste or reference the deliverable]
What you get All 12 seats analyze the deliverable. Solomon identifies patterns (multiple seats see the same issue) and tensions (seats disagree). Full report with verdict.

High-Stakes Decision (Mode C)

/solomon I've been offered a promotion that requires relocating.
My partner doesn't want to move. Pay increase is 40%.
Current role is stable but limited growth. What should I do?
What you get Solomon recommends Mode C. All 12 seats provide exhaustive analysis. Extended deliberation log. Reconciliation matrix (do now / invest now / defer). Strategic applications across 3 tiers. Time horizon analysis (1 week to 5 years). Zero audit jargon — reads like advice from a wise council.

Dr. House Mode (Seat 12)

/c12 full pipeline — We have three teams reporting completely different
root causes for the same production incident. The metrics don't match
any of their explanations. What's actually happening?
What you get Seat 12 (Innovation) activates its Dr. House Differential Diagnosis mode: lists all symptoms, generates competing hypotheses, identifies the one test that distinguishes them. Often reveals the non-obvious answer that explains all the contradictions.

Best Practices

Let Solomon Triage

Don't always force Mode C. Quick questions deserve quick answers. Trust Solomon to read the room and recommend the right depth.

Give Context, Not Commands

Instead of "run Mode B on this", describe the situation and stakes. Solomon triages better with context: "I'm presenting this to the board tomorrow."

Pay Attention to Tensions

The most valuable output is often where seats disagree. Tensions reveal the real decision — the tradeoff you have to make. Don't skip over them looking for the verdict.

Read the Voiceless Seat

Seat 11 (Voiceless/Absent) catches what every other analytical framework misses: the people affected who aren't in the room. This seat alone justifies the Council.

Use for Non-Tech Problems

This isn't a code review tool. It's a thinking tool. Career decisions, family conflicts, legal questions, business strategy — the 12 lenses are universal.

Name Your Tradeoff

If Solomon's verdict doesn't name what's being sacrificed, something went wrong. Every real decision sacrifices something. Knowing what you're giving up is the point.

Anti-Patterns to Avoid

Don'tDo Instead
Run Mode C on "tabs vs spaces" Let Solomon triage — he'll recommend Mode A
Skip Solomon's verdict and cherry-pick seats Read the full synthesis — isolated seat findings miss the interactions
Treat seats as people ("The Adversary thinks...") Treat as lenses ("From an adversarial perspective...")
Expect a "balanced" answer Expect a decision with a named sacrifice
Use only for deliverable reviews Use for any decision where multiple perspectives matter
Ignore the Meaning meta-lens on personal decisions "Who am I becoming?" is often the most important question

When NOT to Use the Council

  • Pure implementation tasks ("fix this null check") — just do the work
  • Information lookups ("what's the syntax for X?") — ask directly
  • When you've already decided and just want validation — the Council may disagree
  • Trivial decisions with no meaningful tradeoff — Solomon will tell you so

How File Loading Works Claude Code's skill loader reads ONLY SKILL.md into context automatically. For Mode A, that's all that's needed — it's fully self-contained. For Mode B/C, SKILL.md contains explicit instructions to load phase files and the report template via the Read tool. This selective-load architecture keeps Mode A fast (~6K tokens) while giving Mode B/C full depth (~25K+ tokens).

Troubleshooting

ProblemSolution
/TrueCouncilOf12 not found Ensure files are at ~/.claude/skills/TrueCouncilOf12/SKILL.md. Restart Claude Code session.
Running on a model the skill doesn't know By design the skill assumes MID band (Modes A/B), says so in the triage line, and proceeds. To grant full Mode C, add the model to the Model → Band Table in SKILL.md.
Mode B/C says "cannot read phase file" Check that ground.md, bound.md, stress.md, elevate.md exist in the skill directory. The skill falls back to Mode A if files are missing.
Output uses audit jargon on a personal problem Prefix with the domain: "This is a personal/career decision." The language adaptation layer adjusts vocabulary. If it persists, report it — the domain rules need strengthening.
Solomon recommends Mode A but I want deeper Say "full council" or "all seats" to override the triage. Solomon recommends, you decide.
Taking too long on Mode A Mode A should finish in <60s. If it's loading phase files, something is wrong — Mode A should never use Read calls. Check that SKILL.md has the "DO NOT use Read tool" guardrail.
Compact model gives poor results COMPACT-band models support Mode A only. For Mode B/C quality, switch to a MID- or FRONTIER-band model (see the Model → Band Table in SKILL.md).
